做机器学习实验，最让人沮丧的时刻之一，是发现上周跑出的好结果，这周怎么都复现不了。

你记得改过学习率，但不确定是不是还换过数据划分；你记得加了正则化，但找不到当时用的系数。日志散在终端里，代码已经被覆盖，最后只能从头再来。

可复现不是学术研究的专利。哪怕只是一个人的项目，它也决定了你是在积累，还是在反复试错。

## 一份最小清单

下面是我现在会坚持的几件事。它们不复杂，但能覆盖大部分「实验失控」的场景。

### 1. 固定随机种子

```python
import random
import numpy as np
import torch

seed = 42
random.seed(seed)
np.random.seed(seed)
torch.manual_seed(seed)
torch.cuda.manual_seed_all(seed)
```

注意：固定种子不等于完全确定。有些 GPU 算子仍然有非确定性，需要额外设置。但至少大部分差异是可追踪的。

### 2. 配置与代码分离

把超参数、数据路径、模型结构都放进配置文件，而不是散落在代码里。

```yaml
data:
  train_path: data/train.parquet
  valid_split: 0.1

model:
  hidden_dim: 256
  dropout: 0.1

train:
  lr: 3e-4
  batch_size: 64
  epochs: 20
  seed: 42
```

每次实验保存一份配置快照。这样你随时知道某个结果是在什么条件下产生的。

### 3. 记录数据版本

代码可以 git，数据也需要版本。

不一定要上很重的工具。至少记录：

- 数据来源和下载日期；
- 预处理脚本的 commit；
- 训练集/验证集/测试集的划分方式；
- 样本数量。

如果数据会变，实验结果就没有可比性。

### 4. 一次只改一个变量

这条听起来很基础，但很容易违反。

同时改学习率、模型深度和数据增强，效果变好了，你也不知道是哪一项起了作用。除非你只是想尽快刷分，否则尽量控制变量。

### 5. 保存日志和产物

至少保存：

- 完整配置；
- 训练日志（loss、指标、学习率）；
- 最终模型或 checkpoint；
- 评估脚本的输出。

日志不要只留在终端里。重定向到文件，或者用一个简单的实验跟踪工具。

## 一个简单的目录结构

```text
experiments/
  2026-09-14_baseline/
    config.yaml
    train.log
    metrics.json
    model.pt
  2026-09-15_lr-1e4/
    ...
```

不用很复杂。关键是每次实验都有独立的位置，不会互相覆盖。

## 最后

可复现的代价是前期多花一点时间；不可复现的代价是后期反复怀疑自己。

当实验变多之后，你会发现真正稀缺的不是算力，而是**对做过什么的清晰记忆**。把记忆交给系统，把注意力留给判断。
